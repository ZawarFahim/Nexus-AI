# Nexus AI
# Database Design Document

**Version:** 1.0

---

# 1. Overview

Nexus AI uses a hybrid storage architecture consisting of:

- PostgreSQL for relational data
- Redis for caching and temporary state
- Qdrant for vector embeddings and semantic search
- MinIO for object storage

Each storage system is responsible for a specific category of data, ensuring performance, scalability, and maintainability.

---

# 2. Database Architecture

| Storage | Purpose |
|----------|---------|
| PostgreSQL | Primary relational database |
| Redis | Cache, sessions, queues |
| Qdrant | Vector embeddings |
| MinIO | Files and uploaded documents |

# 5. Redis Usage

Redis is used for:

- User sessions
- WebSocket connections
- Rate limiting
- Background task queues
- Temporary planner state
- Cached dashboard data

---

# 6. Qdrant Usage

Qdrant stores embeddings for:

- Long-term memories
- Uploaded documents
- Chat history
- Notes
- Research papers
- Browser content

This enables semantic search and retrieval.

---

# 7. MinIO Usage

MinIO stores:

- Uploaded PDFs
- Images
- Audio recordings
- Screenshots
- Workflow artifacts
- Generated reports

Only file metadata is stored in PostgreSQL.

---

# 8. Database Indexing Strategy

Indexes should be created for:

- email
- user_id
- conversation_id
- workflow_id
- created_at
- status
- provider

Composite indexes should be added for frequently queried combinations such as:

- (user_id, created_at)
- (workflow_id, status)
- (conversation_id, created_at)

---

# 9. Security Considerations

- Passwords stored using bcrypt hashing.
- API keys encrypted before storage.
- OAuth tokens encrypted at rest.
- Foreign key constraints enforced.
- Cascading deletes only where appropriate.
- Sensitive data excluded from logs.

# 11. Summary

The database design separates operational data, semantic memory, cached state, and file storage into specialized systems. PostgreSQL serves as the source of truth for application data, Redis improves performance, Qdrant powers semantic retrieval, and MinIO manages object storage. This hybrid architecture supports the current MVP while remaining scalable for future enterprise features.
